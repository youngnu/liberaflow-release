# Liberaflow website & releases

[Liberaflow](https://liberaflow.com)의 제품 소개 사이트와 데스크톱 앱 배포 리소스입니다.

## 사이트 구조

- `index.html` — 한국어·영어 제품 소개, 노트 → 브라우저 → 채널 → Calendar 순서의 네 가지 사용 흐름, 노트 그래프, 로컬/동기화 비교, 4단계 시작 안내, FAQ, 다운로드
- `docs.html` — KO/EN 사용 가이드: 작업별 빠른 찾기, 설치·보관함·노트·지원 문서·편집 단축키·AI·자동화·협업·Calendar·저장과 동기화, 섹션별 실제 사용 순서
- `assets/css/site.css` — 공통 디자인과 반응형 레이아웃
- `assets/css/home.css` — 홈 전용 브랜드 블루 색상, 시작 안내와 반응형 보정
- `assets/css/navigation.css` — 홈과 가이드가 함께 쓰는 상단 메뉴·KO/EN 선택·모바일 메뉴 디자인
- `assets/css/guide.css` — 가이드의 브랜드 블루, 문서 카드·단축키 표·목차·안내 박스와 반응형 레이아웃
- `assets/js/site.js` — 가이드의 기존 공통 메뉴 동작 (보존)
- `assets/js/guide.js` — 읽는 위치에 맞춘 가이드 목차 표시
- `assets/js/locale.js` — 홈·가이드 공통 언어 전환과 페이지 간 언어 유지
- `assets/js/guide-i18n.js` — 가이드 본문·단축키·문서 안내·접근성·메타데이터 번역
- `assets/js/home.js` — 홈의 메뉴·그래프·데이터 비교, Calendar·데이터 뽑기 안내와 노트·채널 예시
- `assets/js/home-i18n.js` — 홈 본문·접근성·메타데이터·동적 데모 번역
- `features/*.html` — 기존 기능 소개 주소를 새 홈의 해당 섹션으로 연결하는 호환 페이지

HTML/CSS/JavaScript만 사용하는 정적 사이트입니다. 빌드나 npm 설치 없이 기존 GitHub Pages 환경에서 제공됩니다. 상대 경로를 사용해 `liberaflow.com`과 `youngnu.github.io/liberaflow-release/`에서 모두 동작합니다.

로컬 미리보기:

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:4173/`를 여세요. 첫 화면은 노트로 문서 만들기입니다. 마지막 Calendar 탭에서는 개인 일정·오늘 할 일과 팀·팔로우 일정 안내를 전환할 수 있습니다. 노트·채널의 원본 자료/예시 결과, 브라우저의 데이터 뽑기/내보내기 안내, 키보드 방향키 탐색과 모바일 메뉴도 확인할 수 있습니다. 내용은 바로 표시하며, 실제 작업을 수행하는 것처럼 보이는 실행 대기나 진행률은 사용하지 않습니다. 일정 생성·공유, AI 호출·브라우저 실행·사용자 자료 전송을 하지 않습니다. JavaScript가 없어도 노트 소개·가이드·직접 다운로드 링크는 이용할 수 있습니다.

언어별 직접 미리보기는 `http://127.0.0.1:4173/?lang=ko`와 `http://127.0.0.1:4173/?lang=en`입니다. 주소의 언어 설정을 우선하고, 선택한 언어는 브라우저에 저장합니다. 아무 설정이 없으면 한국어로 시작합니다. JavaScript가 꺼져 있으면 한국어 본문과 다운로드를 제공합니다. 가이드는 `http://127.0.0.1:4173/docs.html?lang=ko`와 `http://127.0.0.1:4173/docs.html?lang=en`으로 확인합니다. 홈과 가이드 사이를 이동해도 언어를 유지합니다.

## 링크 공유 미리보기

- 홈페이지의 Open Graph와 Twitter 카드 이미지는 `assets/images/liberaflow-social-preview-v1.png`를 사용합니다. 1200 × 630 PNG에 서비스 설명과 홈페이지의 **노트로 문서 만들기 사용 예시**를 담았습니다. 앱 화면 캡처가 아닌 홈페이지 예시임을 이미지에 표시합니다.
- 편집 원본은 `tools/social-preview.html`입니다. 위 로컬 미리보기 서버에서 해당 경로를 열면 현재 홈페이지의 노트 예시를 불러옵니다. 브라우저 크기를 1200 × 630으로 맞추고, `document.documentElement.dataset.ready === "true"`가 된 후 화면을 PNG로 캡처합니다. 홈페이지의 화면 구성이나 문구가 바뀌면 이미지도 다시 생성해 커밋하세요.
- 이미지를 갱신할 때는 파일명 버전과 `index.html`의 `og:image`·`twitter:image` URL을 함께 바꾸세요. 이미지 크기·형식·대체 설명도 실제 파일과 맞추고, 공유 문구를 바꾸면 `assets/js/home-i18n.js`의 영어 번역도 갱신합니다. 공유 메타데이터는 JavaScript 없이 읽을 수 있도록 HTML에 둡니다.
- 배포 후에도 카카오톡에서 이전 미리보기가 나오면 [카카오 초기화 도구](https://developers.kakao.com/tool)의 **OG(Open Graph) 캐시**에서 공유한 웹페이지 URL을 초기화합니다. 이미지 URL 변경만으로 기존 페이지 캐시가 즉시 갱신되지는 않습니다. [공식 FAQ](https://developers.kakao.com/docs/ko/message-template/faq)

## 브랜드와 수정 경계

앱 저장소 `window_automation/assets/icon/Liberaflow_logo.png`와 같은 원본 로고를 그대로 사용합니다. 홈은 로고의 블루를 중심으로 네이비·차가운 흰색을 조합하고, 기존 레이아웃과 인터랙티브 데모를 유지합니다. 작은 글자의 명암 대비를 위해 버튼·링크의 블루는 용도에 맞게 밝기를 조정합니다.

홈 전용 CSS와 `home.js`는 `index.html`에서만 불러옵니다. `docs.html`도 수정 범위에 포함하며 `guide.css`로 홈과 같은 색상을 적용합니다. 상단 메뉴 디자인과 언어 전환 동작은 두 페이지가 공유합니다. 공통 기반 `site.css`와 기존 `site.js`는 그대로 둡니다. 홈·브랜드 개편에서는 `updates/appcast.xml`, `email-confirmation.html`, `reset-password.html`과 원본 로고를 수정하지 않습니다. 릴리스 또는 인증 보안 변경은 별도 작업으로 분리하고 실제 업데이트·Supabase 복귀 흐름까지 검증합니다.

사용 안내는 앱 저장소의 `README.md`와 `ARCHITECTURE.md`를 기준으로 합니다. 본문이나 데모의 한국어를 바꿀 때는 해당 페이지의 `home-i18n.js` 또는 `guide-i18n.js` 번역도 함께 갱신하세요. 언어를 바꿔도 원본/결과 표시 상태, 선택한 탭·노트, 펼친 안내는 유지됩니다.

## 사용 예시의 기준

홈의 예시는 실제 앱 화면 캡처가 아니라 사용 순서를 설명하는 구성입니다. 사용자 준비·입력과 결과를 구분하며, 결과에 원본에 없는 사실을 추가하지 않습니다.

- Calendar: 기능 소개의 순서에 맞춰 홈페이지의 마지막 탭으로 배치합니다. 기능 소개는 노트 작성·연결 → AI → 자동화 → 팀 협업 → Calendar 순서로 소개합니다. 개인 일정·Tasks의 **오늘의 할일**은 로그인 없이 시작합니다. 로그인 후 **설정 → 팀**에서 팀 생성·멤버 초대, 또는 **설정 → 사람**에서 팔로우 요청을 하고 상대가 수락하면, 내 일정과 연결된 사람들의 공개 일정이 같은 Calendar 화면에 표시됩니다. 같은 팀이면 별도 팔로우가 필요하지 않습니다. 공개 일정은 팔로워·같은 팀원에게, 비공개 일정은 작성자·지정한 참석자에게만 표시됩니다. `ARCHITECTURE.md`의 **4. Calendar**, 일정 편집기의 공개 범위 안내와 캘린더 표시 로직을 함께 확인합니다.
- 노트: 모델 연결 → `@` 목록에서 자료 선택 → Word 형식을 명시해 요청 → 미리보기·수정. `출시 준비.md`의 미정 항목은 결과에서도 미정으로 유지합니다. 파일 생성만으로 공유가 완료되지는 않습니다.
- 브라우저: 확장의 **데이터 뽑기**에서 값 선택 → **앱으로 보내기** → 앱에서 **단계로 추가** → 추출 단계 뒤에 **파일 내보내기** 추가 → **파일 형식**에서 **CSV 또는 XLSX** 선택·파일 이름 확인·단계 삽입 → **Replay** → 완료 창의 **파일 열기**. 이 흐름에 녹화나 입력 CSV는 필수가 아닙니다. 가상의 검색어·수집 결과 표를 만들지 않고 실제 기능과 조작 순서만 안내합니다. ARCH의 **브라우저 안에서 만드는 추출 규칙**, **실행 결과의 표면**을 기준으로, 결과는 앱 내부의 표가 아니라 내보낸 파일로 확인한다고 설명합니다.
- 채널: 로그인·AI 팀원 초대·문서 공유 → `@` 자료와 `#` 팀원을 목록에서 선택 → 채널에서 답변 확인. 예시는 Reviewer 한 명을 호출합니다. 여러 팀원을 한 요청에 넣는 동시 호출과 답변 속 멘션으로 이어지는 인계를 혼동하지 않습니다.

기준 문서: 앱 `README.md`의 **노트 옆 AI 에이전트**, **Channel**, **에이전트 허브**와 `ARCHITECTURE.md`의 **1-4**, **10-1**, **10-2**, **10-3**. 원본 자료·사용 순서·표시하는 결과를 함께 검토해 주세요.

## 배포·인증 리소스

디자인 변경 시 다음의 주소와 기존 동작을 보존하세요.

- `updates/appcast.xml` — 앱 자동 업데이트 피드와 서명
- `assets/js/download-config.js` — 다운로드 URL의 중앙 설정
- `reset-password.html`, `email-confirmation.html` — 인증 이메일의 복귀 경로
- `CNAME` — 기존 도메인
- `privacy/browser-automation/` — 확장 프로그램 개인정보처리방침
- `naverbc95ad0893d4f5b76c2c91972731d8bb.html`, `robots.txt` — 사이트 인증과 크롤러 정책
- `extension-test.html`, `extract-test.html` — 브라우저 확장 진단 페이지
- `release.sh`, `RELEASE_GUIDE.md`, `HOSTING_MIGRATION_GUIDE.md` — 기존 릴리스 운영 자료

다운로드 버튼의 `macosBtn` / `windowsBtn` ID는 중앙 설정을 적용하는 안정적인 연결 계약이므로 유지합니다. 릴리스 시 `assets/js/download-config.js`의 중앙 설정과 HTML의 JavaScript 미사용용 직접 링크를 함께 갱신하고, `release.sh --check`로 두 값과 appcast 메타데이터의 일치를 검사하세요.

비밀번호 재설정 페이지는 `token_hash`와 `type=recovery`를 사용하는 Recovery 이메일 템플릿 또는 `type=recovery`가 포함된 implicit 토큰만 처리합니다. 데스크톱 앱에서 시작한 PKCE 코드의 verifier는 브라우저에 없으므로 `?code=`를 웹에서 교환하지 않습니다. Supabase Recovery 템플릿과 실제 이메일 링크를 함께 설정·검증하세요.

기존 홈의 `#features`, `#vision` 앵커는 각각 새 기능 소개와 데이터 소유권 섹션에 연결됩니다. `#download`, `#faq` 주소도 유지됩니다.

제품 설명은 인접 앱 저장소의 `README.md`와 `ARCHITECTURE.md`를 기준으로 작성했습니다. 공식 다운로드 지원은 Windows 11 이상과 macOS 15 이상 Apple Silicon입니다. 앱·모델 제공자의 계정과 과금은 서로 구분합니다.

## 가이드 내용 검증 기준

- 편집 단축키는 `note_screen.dart`와 앱에 포함된 `flutter_quill` 키 등록·동작을 확인합니다. 주 노트 편집기, 찾기 입력창, 표 셀의 조건을 구분합니다. 하이라이트는 범위 선택이 필요하고, 저장 단축키나 충돌하는 키는 추정해 추가하지 않습니다.
- 지원 문서는 `note_screen.dart`, `office_preview_service.dart`, `html_file_viewer.dart`, `pdf_viewer.dart`, `image_file_viewer.dart`를 확인합니다. 노트·캔버스·로컬 HTML 직접 편집, Office 원본 AI 편집, PDF·이미지·CSV/TSV 열람 범위를 구분합니다. 영어 명령은 `agent_slash_command.dart`의 실제 별칭을 사용합니다.
- 브라우저 화면 캡처 설정은 현재 확장 팝업 기준으로 설명합니다. README의 과거 기본값보다 실제 구현을 우선합니다. 놓친 예약의 24시간 조건, 클라우드 노트·캔버스의 30일 복구 조건을 명시합니다. 보관함 전체 파일 자동 동기화로 과장하지 않습니다.
- 확인: KO/EN 전체 본문과 접근성 이름, 홈↔가이드 언어 유지, 같은 너비의 상단 메뉴 일치, 목차 이동, 모바일에서 양쪽 운영체제 단축키 표시, 펼친 안내 상태 유지, JavaScript 미사용 시 한국어 본문·다운로드.

가이드의 기호 입력 서식은 접지 않고 입력 순서·변환 결과·체크 목록 작성 예시를 함께 제공합니다. `[]`는 공백 없는 입력이며, 제목 아래 빈 본문 줄에서 시작합니다. AI 대화 명령 표에는 `@` 문서·폴더 참조를 포함합니다. 브라우저의 `⋮ → 가이드 문서 만들기 (md)`는 현재 기능이고, 저장한 브라우저 워크플로를 AI 스킬로 호출하는 연결은 **개발 예정**으로 구분합니다. AI 호출과 데이터 전송을 줄일 수 있는 구조를 설명하되, 가이드 생성·AI 작업·자가치유의 전송 범위를 별도로 명시합니다.

추가 사용 안내는 ARCH의 Notes·Settings·Agent Hub·Channels·Spaces·Calendar 절과 해당 UI 코드를 대조합니다. 자료 가져오기와 정리, 검색 필터, 분할 보기, 제목 링크, Office 부분 수정, 스킬 생성, 워크플로 저장·이동·단계 수정·실행 점검, 공유 노트 수정 제안, 채널 메모, 지식 공간, 일정 상세, 바탕화면 위젯, 예약 관리, 협업 알림, 저장 상태와 복구를 설명합니다.

사용 조건도 실제 동작과 함께 유지하세요. 로그인 후 타인이 공유한 클라우드 노트에 수정안을 제안할 수 있으며, 내 보관함의 동기화를 켤 필요는 없습니다. 위젯의 핀은 다음 앱 실행 시 자동 복원을 뜻합니다. 일반 AI 스킬의 현재 기능과 브라우저 워크플로를 AI 스킬로 호출하는 예정 기능은 구분합니다. 작업별 빠른 찾기와 각 섹션의 바로가기는 기존 10개 목차·기존 앵커를 유지하면서 하위 안내로 연결합니다.
